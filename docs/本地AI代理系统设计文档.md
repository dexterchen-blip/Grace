## 0. 一句话定位

**隐私沙箱 + 桌面常驻 AI 伙伴**。不是云端 coding agent 的替代品，是具备以下能力的本地代理：  
文件编辑、本地知识库、本地长期记忆库、网页搜索、与 WorkBuddy 文件夹互传、独立常驻信息窗口。  
（多 agent 分发**不是**本系统的运行时能力，而是我——洛琪希 / 主 agent——正式开工时的构建工作方式，见 §16。）

## 1. 目标机器事实（已核实，Apple 官方规格页）

- M5 Pro 于 2026-03 发布；内存带宽 **307GB/s**（M5 Max 460 / 614）；**48GB 是 M5 Pro 合法配置**；1TB 起步。
- SSD 读写宣称最高 **14.5GB/s** → 模型热切换成本仅几秒，**分层 / 异构模型架构可行**。
- 70B 4-bit 权重约 **47GB（Q4_K_M）、4-bit 下界约 38GB**；实测解码预计 **5–6 tok/s**（需 64GB 机型）；KV cache（32k 上下文）再吃 5–10GB。**但含 KV 后 70B 实际需 45–52GB，远超 48GB 夜班 36GB 预算——70B 在 48GB 上装不下（含 KV 是硬约束）。**
- **关键内存约束（2026-08 修正）**：白天 macOS 10–12GB + 浏览器/IDE 8–10GB → 仅 26–30GB 给模型；凌晨 04:00 桌面清空时可用约 36GB。**原"70B 恰好成为夜班专属重炮"已证伪**——70B 含 KV 需 45–52GB，48GB 装不下。夜班实际选型见 §2：**Qwen3.5-35B-A3B Q6_K（~29GB，llama.cpp/GGUF）**（注：2026-08-17 定稿已将原 40B 方案替换为 35B-A3B MoE），真·70B 留作 **64GB+ 机型 DLC**。

## 2. 模型分层（Q2 / Q14 / Q15）

- **白天**：20GB 级模型（Ollama，OpenAI 兼容 API），随用随载，绝不长期占满内存。
- **夜间（夜班分析师 / 记忆巩固）**：**Qwen3.5-35B-A3B Q6_K（~29GB，含 KV，MoE 35B总/3B激活）**，经 **llama.cpp** 运行（GGUF 量化，Metal）；**白天绝不加载**。
- **保守备选（留 MLX）**：若 llama.cpp 不便，改用 **Qwen3.8-27B（MLX 原生，峰值 15.5GB，已实测 17.3 tok/s，GDN hybrid）** 或 **Qwen3-32B Q5_K_M（MLX）**——质量对巩固够用。
- **原"70B 夜班"已证伪**（研究备忘 `70B部署可行性研究-kv缓存.md`）：70B 4-bit 47GB + 32k KV 10.5GB = 57.9GB，48GB 装不下；真·70B 留作 **64GB+ 机型 DLC**。
- **框架说明（修正，2026-08-17 实测）**：**MLX 已实测支持 GDN 混合层**——白天 Qwen3.8-27B（GDN hybrid）MLX 跑通（15.5GB/17.3 tok/s）。夜班选 llama.cpp 因其 GGUF 量化成熟、29GB MoE 在 Metal 稳定；`ctx.llm` adapter 即插即用，切换不影响架构。
- **⚠️ 上线前核查（2026-08-17 实测更新）**：① 确认取 **干净 base**（私人记忆系统建议用未改写 base，避免 persona 污染事实记忆）；② 夜班框架锁定 **llama.cpp（GGUF）**——35B-A3B 的 GDN+MoE 层在 llama.cpp 量化成熟、Metal 稳定；**MLX 已实测支持 GDN（白天 Qwen3.8-27B GDN hybrid 跑通），「MLX 不支持 GDN」旧结论已证伪**，MLX 可作白天主力。
- 参考档位（2026-08-17 定稿）：夜班 **Qwen3.5-35B-A3B Q6_K ≈29GB（GGUF，MoE 35B总/3B激活，实测 27.6–49.4 tok/s，Apache 2.0）**；白天 **Qwen3.8-27B 4bit ≈15.5GB 峰值（MLX，GDN hybrid，17.3 tok/s）**。

## 3. 记忆四层（Q9 / Q18 / Q24）

| 层          | 作用           | 规则                                 |
| ---------- | ------------ | ---------------------------------- |
| **L0 原始层** | 微信/邮件/文件原始落盘 | **只追加，永不删**。"遗忘"= 掉出索引，原文永在        |
| **L1 工作层** | 短期工作记忆       | 30 天滚动                             |
| **L2 语义层** | 可检索长期记忆      | sqlite-vec + bge-m3 + 向量/BM25 混合检索 |
| **L3 核心层** | 常驻上下文        | 约 2000 token；新增直接生效，修改/删除需点头       |

- **嵌入粒度**：按会话切片（间隔 <30 分钟为一段）；丢公众号（`gh_*`）；丢表情/图片；保留 `msg_id` 范围可回捞 L0。
- **遗忘哲学**（参考 OpenClaw / Zep / Letta）：L0 永不删；遗忘 = 从索引降级，旧边弃用而非覆写。

## 6. 人格（Q20 / Q23 / Q28 / Q34）

- Megumin 走**可热插拔 LoRA**（`--adapter-path` 挂载，**永不 fuse**；fuse 不可逆，且 `merge_lora` 不支持 unmerge）。

- **手动开关**；**睡眠时段绝不挂人格 LoRA**。
- **抽取污染隔离**：每条对话打 `mode` 标签（`normal` / `persona`）；巩固只把 `normal` 喂进事实记忆（L0/L1/L2）；`persona` 模式隔离到 `persona/` 子树，永不进语义索引、不参与"想起某事"的检索。

## 7. 隐私（Q8 / Q20 / Q25）

- 出网可抓公开网页；**本机文件内容永不外发**。
- `exchange/` 协议：inbox / outbox / shared / archive；`sensitive: true` 只落 shared，不进 outbox。
- 工作目录**不加密**（本地 AI 频繁读写）；Time Machine 手动 1–2 月同步一次。
- 本地安全备份：记忆核心（几 MB 级）用 **git 版本化快照**，用于撤销而非灾备。
- 构建期多模型分工（§16）属开发效率安排，**不改变**本机优先、文件内容不出本机的运行时红线。

## 8. 学校文件夹 + 写回（Q26 / Q31 + Q32）

- 专门子文件夹存学校日程表 / 作业表，做结构化抽取驱动 dashboard。
- **写回安全边界**：仅"用户显式动作"才写回——
  - 侧边栏状态按钮点击；或

- 每次写回落 **`audit.log`（只追加）**；单条记录单文件存储，便于 git 回滚。

## 11. 微信 launchd 修复（已完成 ✅，Q11 / Q19 / Q21）

- **根因**：原 `StartInterval=172800` 从 load 时刻起每 N 秒，**重启清零计时器** → 长周期任务碰频繁重启永远跑不到（8/07 那次 bootstrap 静默失败，唯一一次运行是手动跑的）。
- **修复**：改 `StartCalendarInterval` 每天 04:00（与睡眠周期对齐）；`~/Library/LaunchAgents` 与项目内两份 plist 同步。
- **重 bootstrap**：走 osascript 管理员路径（沙箱里直接 `launchctl bootstrap` 报 error 5）。
- **验证（2026-08-10 17:30）**：
  - `launchctl print` 确认 event trigger = `com.apple.launchd.calendarinterval, Hour=4, Minute=0`；
  - `kickstart` 跑通：解密 26 个 DB（HMAC OK）、读 55 条新消息、产出 `digest-2026-08-07.md`。
