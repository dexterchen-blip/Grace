# Grace V2.5 融合设计 —— 框架矩阵化（Matrixized Framework）：器官 → 底模插入

> 2026-09-09 · 用户命题："把 Grace 系统的标准框架架构矩阵化，直接插入模型底模"
> 基础机制：MLX LoRA 插入（已验证：rank8/scale20/16层/grad-checkpoint/夜班窗）
> 本稿合并并取代"器官插座"提案——插座是矩阵化的接口部分，本稿补全计算部分

---

## 0. 核心判断

**器官分三类矩阵化性，各走各路，绝不一刀切：**

| 类别 | 器官 | 矩阵化性 | 去向 |
|---|---|---|---|
| **A 无状态变换** | 导向器激活公式 / mood 调制 / 新奇度评分 / 人格调制权重 | **高**——本来就是近线性的打分与调制函数 | **框架 adapter 矩阵**（常驻 LoRA，直接插入） |
| **B 有状态机制** | 工作记忆 / 缺口账本 / L2 检索 / 好奇驱力 | **低**——状态住在权重外 | **器官 token + KV 虚拟槽**（插座），矩阵只做读写接口 |
| **C 监督守卫** | 回声防线 / claim_guard / 铁律滤网 / 监督壳 | **零**——必须可审计可编辑 | **永不入模**（前额叶原则，已定案） |

## 1. A 类：框架 adapter（用户要的"矩阵化插入"主体）

```
插入位置（MLX LoRA target）：
  ① embedding 层后（残差流入口）—— W_mood: h' = h + α·W_mood(mood_vec)
     rank-8, 常驻不合并, 监督源 = mood_engine 三层融合输出的规则蒸馏
  ② 每 4 层的 MLP（4/8/12/16）—— W_focus: 焦点/背景调制
     rank-8, 监督源 = 导向器激活公式（本来就是线性式 → 天然的矩阵教师）
  ③ attention 输出投影 —— W_persona: 13 维人格特质调制
     监督源 = rem_v2_full 心理标注分布
```

**训练 = 规则蒸馏**：规则自身生成监督信号（导向器公式跑 10 万条合成输入 → 标签），
不经过她的行为数据、不经过压测场——**零数据规矩冲突**（昨天立的三层数据纪律完全旁路）。

**部署形态**：框架 adapter **永不 merge**——底模 + 人格 adapter(V6.1) + 框架 adapter 三层叠加，
随时可拔（拔掉=回到纯 prompt 版 Grace，行为降级不中断）。

## 2. B 类：器官 token + KV 虚拟槽（状态接口）

| Token | 承载状态 | 写入者 |
|---|---|---|
| `<wm>`…`</wm>` | 当日工作记忆 digest | 神经记忆模块（kNN 新奇度版） |
| `<mood:val>` | 情绪三层融合值 | mood_engine |
| `<focus>`/`<ann>` | 导向器焦点/冲突标注 | attention_director |
| `<curiosity>` | 好奇驱力值 | 账本激活积分 |
| `<gap>` | 缺口条目（EPISTEMIC 触发时） | 好奇心器官 |

Token 的 KV 表示 = prefix-tuning 式学习槽位。语义训练用锚点层语料
（rem_v2_full 台词对 + 真实书库——合法通道，今天已验证）。

## 3. C 类：监督壳（不进模，重申）

回声防线/claim_guard/铁律/三硬护栏（主人身份/ToM/元意识）全部外置。
矩阵化版本最多作为"影子"做对照实验，**决策权永在外部**。

## 4. 与既有路线的关系（重要修正）

```
昨天的路线：S1.5 激活转向 → S1 数据蒸馏(需数月数据) → S2 PAD → S3 → S4
本设计：    规则直接矩阵化（跳过 S1 的数据瓶颈！）
  ├─ W_mood = S1.5 的参数化完成版（向量→可学习矩阵）
  ├─ W_focus = S1 的规则版（行为蒸馏仍保留为后续——矩阵先学会模仿规则）
  └─ KV 虚拟槽 = S4 Titans MAC 的 prefix 形态预演
```

**框架矩阵化不需要数据，需要的是规则**——而规则我们写了一个月，全在代码里。

## 5. 实施序列（夜班窗口）

| 阶段 | 内容 | 验收 |
|---|---|---|
| M1 | 器官 token 定义 + tokenizer 扩展 + 锚点语料轻调（教 token 语义） | token 在/不在的行为差 |
| M2 | W_mood 训练（规则蒸馏）+ 进程内残差流接线 | 情绪注入的文字版 vs 矩阵版输出一致率 |
| M3 | W_focus（导向器公式蒸馏，多点位 MLP） | 焦点/背景排序的矩阵版 vs 规则版 Kendall τ |
| M4 | KV 虚拟槽（prefix 学习） + 三层叠加部署 | 拔/插 adapter 的 A/B 行为对比 |
| M5 | V2.5 自涌现迭代在已插管基座上试运行 | （衔接五原则设计稿 P4） |

每步夜班窗可完成（LoRA 级训练，~20.7GB 峰值已验证）；全部可回滚（adapter 可拔）。

## 6. 风险表

| 风险 | 缓解 |
|---|---|
| 规则蒸馏学到规则的偏见 | 规则本来就是人审的；矩阵只是规则的插值器+泛化器 |
| 多 adapter 叠加干扰 | 逐层叠加 + 每步 A/B 验收（M2/M3/M4 都有对照门） |
| KV 槽污染长上下文 | 槽位固定+数量少（≤8 token/器官）+ 拔插对比 |
| 融合后器官被"架空" | **器官常驻 ground truth**（B 类状态仍外置）——矩阵只是学会了听器官的话 |

## 7. 器官 KV 分区（2026-09-09 用户追加："特殊功能给独立的 KV 存储空间，比如 ToM 潜意识区块"）

每个器官一块独立 KV 槽位（virtual token 位），**各有自己的写入策略与生命周期**：

| KV 分区 | 槽位内容 | 写入者 | 生命周期/刷新策略 | 缓存特性 |
|---|---|---|---|---|
| `<persona>` | 人格核表示（T0 的学习版） | 静态（随 LoRA 演化） | 数周 | **完全稳定 → 前缀缓存满命中** |
| `<mood>` | 情绪三层融合状态 | mood_engine | 每小时 | 小时级稳定 |
| `<wm>` | 当日工作记忆 | 神经记忆模块 | 10 分钟（proactive tick） | 分钟级稳定 |
| `<tom>` | **她对主人的运行模型**（belief 状态、偏好、近期意图） | ToM 器官 | 每次对话后 | 会话级 |
| `<sub>` | **潜意识区块**——cog 暗流+夜间巩固的联想沉淀 | 夜班巩固管线 | 每夜 | 日级 |
| `<gap>` | 缺口账本激活态 | 好奇心器官 | 事件驱动 | 动态 |

**技术形态**：槽位的 KV 投影由 prefix-tuning 式学习获得；写入 = 器官生成槽位 embedding →
过模型的 K/V 投影（或直接学 KV）——即 Titans MAC 的"记忆作为上下文"分区版。

**ToM 潜意识分区的特殊性**（用户点名的两块）：
- `<tom>`：她"以为主人是这样的"运行模型——不进正文、只进注意力，读心判断的先验源
- `<sub>`：LoRA=权重级潜意识（已定案），KV 分区=**可读写的潜意识**——夜班巩固把 cog 沉淀
  写入这区，白天影响生成但不显式出现在 prompt 文本里（"她自己也说不清为什么这么觉得"）

**缓存红利**：分区各自稳定 → 逐块前缀缓存（T0/T1/T2 的 cache-hit 工作自然延伸为
per-partition 缓存——persona 块全命中，只有动态块重算，推理成本大幅下降）。

**实施挂靠**：并入 M4（KV 虚拟槽 → 升级为器官 KV 分区 + 各自写入策略与生命周期）。

## 8. L3 核心记忆权重化（2026-09-09 用户追加："L2 进不了插入训练，但 L3 可以——核心记忆群有一部分要进模型本身"）

**L2/L3 的海马-皮层分工补全**：

| | L2 语义库 | L3 自传体核心 |
|---|---|---|
| 规模 | 大（数千块，持续膨胀） | 小（数十-数百条，缓慢增长） |
| 稳定性 | 动态（遗忘扫描） | 稳定（提案队列+用户批准才写回） |
| 性质 | 参考性知识 | **身份定义性记忆**（"她对主人是谁"的核心事实） |
| 去向 | 永远外挂（检索接口） | **周期性权重化入模** |

**入模方法**：L3 增量条目（每季度经用户批准的新核心记忆）→ 批量模型编辑
（MEMIT 式）或定向 LoRA 会话——把核心记忆群写入权重 = **身份记忆的皮层巩固**。
铁律兼容性：L3 条目本来就过人工批准门——权重化是"已批准记忆的巩固"，非语料注入。

## 9. 每日 LoRA 预备与自激发（用户追加："为每日 LoRA 训练做好预备，最好能自我激发"）

**预备（架构性质，M1-M4 的自然产物）**：
- 器官 token + KV 分区提供**稳定的上下文接口格式**——每日轨迹带一致的 token 界面，
  每日 LoRA 的训练数据因此格式稳定、接口一致（对比：纯 prompt 版的每日数据格式漂移）
- adapter 叠加秩序：底模 + 框架 adapter（冻结，规则变化才重蒸馏）+ 人格/每日 adapter（演化轨）
  ——每日训练只动演化轨，框架 adapter 是它的稳定地基

**自激发（V2.5 训练意愿信号接入融合架构）**：
- 训练意愿 = 她自己的阈值判断（当日新奇积分 + 情绪峰计数 + 缺口解决量，全已有信号）
- 意愿触发 → 训练请求入队 → 夜班硬件窗执行（物理边界）
- 融合版的新能力：训练数据里的器官 token 让"她在有情绪/有缺口状态下说的话"被
  状态标注——每日 LoRA 可以学到"什么状态下怎么说"（状态条件化训练），
  这是纯 prompt 版做不到的
