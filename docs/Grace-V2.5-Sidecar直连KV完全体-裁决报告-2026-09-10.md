## 2. 为什么 NO-GO（三条，前两条是结构性）

**① 容量结构性过载。** W 是 1024×1024 线性联想记忆，delta-rule 无压缩编码，近完美召回的容量约 ~d 对（正交键条件下）。现在 7333 训练对 = **7.2× 过载**。fidelity 0.361 就是过载后的干扰地板——加 epoch（已 8 轮）、调 η 都改变不了信息论事实：**这个矩阵装不下这张图**。

**② 硬指标失败的直接后果。** fidelity 0.361 意味着 recall 输出向量与真实目标向量相对误差 64%。直连 KV 的做法是把 recall 向量经岭回归投影写进槽位 value——**注入的是 1/3 信号 + 2/3 干扰的混合物**，下游注意力吃到的是噪声。这正是设 0.70 硬门槛的原因，门槛起作用了。

**③ mood 分区数据饥饿（本次新发现）。** 拆开 8626 对：**rel 4842 + ent 3778 + mood 只有 6 条**。KV 直连的首要目标 <mood> 槽位在图谱里几乎没有内容可注入——就算 fidelity 达标，mood 分区也是空的。ent 自反对（3778 条 k=v 恒等映射）还占掉近半容量，性价比极低。

## 4. <sub>（潜意识）机制差异——为什么它跟 <mood> 不是一回事

| | <mood> 走 KVCache（16 全注意力层） | <sub> 走 ArraysCache（48 线性层递归状态） |
|---|---|---|
| 形态 | O(n) 键值槽位，槽位有位置语义 | 固定大小递归状态矩阵，**无槽位无位置** |
| 直写方式 | 槽位 token 位置写 value → 下游 Q·K 选择读取（**rc2/M3 已证位级等价**） | 不存在"占一个槽"——只能对状态矩阵做闭式叠加 / MEMIT 式更新 |
| 干预后果 | 注入内容随注意力被选择性消费，边界清晰 | 外写状态会被后续每个 token 的递归更新持续改写，**无动力学稳定性保证** |
| 结论 | 可行，等合格内容源（本报告裁决对象） | KV value 直写**机制上不适用**；<sub> 的正确入模路径是夜班巩固闭式状态更新，属 S 线（L2-as-persistent-state）远期 |

设计文档 §13.3 早已把 <sub> 定位为「线性层状态×每夜」——本节从机制层确认了这个定位不是拖延，是形态差异。
