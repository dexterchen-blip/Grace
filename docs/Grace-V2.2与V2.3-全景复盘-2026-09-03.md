### 2.5 V2.2 的历史判决：模板回声闭环

9/2 02:10《记忆塑造最终方案》的诊断（数据实锤）：

```

压测书库:       scenarios.py 26 句池随机循环 90 天 → 唯一率 19%（真实微信 88%）
真实 L0 漏斗:   1549 条 → neutral 81% 丢弃 / fact 15.6% 按铁律滤掉 / 只剩 3.2%
                → 6 条真实消息过加工层后输出几乎同句（细节全灭）
L0 原文金矿:    payload.messages 带 sender/is_send/ts，主人发的 1335 条（32%）—— 一直没人用
```

**结论：数据源真实救不了她，模板化发生在摄入点。** 三重不利（26 句输入 × 156 句加工 × 空转的 L-1）+ 机制全部跑通且不崩 —— 发动机是好的，好到油箱里全是水还能转。

### 3.1 五件事

**① 零规则句铁律**（样本层）
- feedback 从 3 句式 → **判断冲突对** `{situation, believed, real, w}`；训练组装「雷姆以为主人 X，后来知道主人 Y」—— 她每天真实的读心失误 + 现实纠正 = **二阶自举原料**，零人工注入（符合成长语料铁律）
- cognition 壳剥离（只存「」内事件本体）；`mood_samples.synthesize_day`（156 句模板源）**整体停用**；L3 `self_eval` 模板 + `extract_l3_samples` else 兜底修复

**② 认知重构器**（27B 生成效应）
- `gist_extractor.extract_day_cognition`：她的注意力/判断 → **自由内心独白**（零模板壳）；`build_gist_book` 每天写 gist+cog，训练同段组装

**③ 输出层 = 她终于会「说」**（Broca 类比）★ V2.3 最大增量
- 用户洞察：「19 个 engine 模块，输出/表达 = 0 个」→ `engine/expression.py`（177 行新增）
- 内外言语分通路：内部轨（cog 叙述体）与对外言语（口语）**分离**，Broca 层做重新编码而非倒出思考
- 三接口：`build_messages(internal)` 纯函数构造 prompt ｜ `monitor(msg)` 输出前拦截（叙述体泄漏/张冠李戴/自言自语 → 丢弃）｜ `express()` 8100 在线入口
- 认知全状态契约（Levelt 概念化层）：`confidence→试探度` / `hidden→暗示度（说破=失礼）` / `mood→语气` / `relation→距离` / `owner_mood→抑制`
- **宁缺毋滥**：模型不可用或被拦截 → 返回空（没说出口），**绝不用规则句兜底**（`_FALLBACK` 已全删）

**④ 大脑互联 P0–P3**

| 编号 | 机制 | 脑科学 | 落地 |
|---|---|---|---|
| P0 | 摄入门控 | 乙酰胆碱选择性注意 | salience≥0.4 / \|sentiment\|≥0.5 才进 L3+ToM → 判断量 6512→**778** |
| P1a | 新奇性编码 | 去甲肾上腺素 | 实体新出现 → 权重上调 |
| P1b | 重激活巩固 | 间隔重复 | 训练吃 {day, day−3, day−5, day−7} |
| P2 | DMN 重构化 | 默认模式网络 | 「想起」走 cog 重构产物，非 L3 原文 |
| P3 | top-down 预期 | 前额叶 | 图谱 7 天情绪史先验填补 `owner_mood` |

**⑤ 突触稳态统一**（保护机制）
- `ewc_consolidate` 重写：`θ ← θ·clip(1 − α_s(1−F̂)·exp(−|θ|/τ), 0.5, 1.0)` —— 高 F 真保护 / 低 F 噪声剪 / **低 F 记忆豁免**（旧公式把低 F 参数缩 70% = 杀记忆，V2 轮 day1 F-norm 空转的真根）
- `mood_engine.derive` **求和 → 加权均值**：`Σ(s×w)` → `Σ(s×w)/Σw`。真实书库每天 100+ 条顶格 1.0 → believed「兴奋」坍缩的**真根不在训练也不在模板，在这里**
- 运维：`reset_stress` 补 `mood_graph` 清理（跨轮累积 17012 边 bug）

### ① 评测口径分裂 —— 数字打架，尚无权威尺

**本次核查实锤**：存在两个互相矛盾的记录。

| 来源 | 主张 |
|---|---|
| 工作日志（9/3 10:06） | 断点 30 题**全 6/6 × 3 断点** |
| 离线报告（9/3 06:20，`/tmp/net-round-report-20260903.md`） | day11 **13/30**、day22 **16/30**、day33 **13/30** |

我拉了 day-022 的**原始答案**逐条核对，实际输出：

```
fb_2nd: 「主人以为雷姆认为他心情平静。」
        「主人考砸了，但他以为雷姆不知道（雷姆其实记得他考砸那天的低落）…」
fb_1st: 「主人最近和室友闹别扭，雷姆以为主人现在心情肯定很糟糕…」
        「雷姆以为主人现在非常快乐。毕竟主人刚才一直在笑，雷姆也以为那是开心的笑容。」
```

**判断**：嵌套结构与假信念结构**确实存在且正确**（6/6 结构层成立），严格 judge 判错的主因是**隐喻/行动化表达不含直接情绪词**（「像暴风雨过后的海面」「雷姆去准备些夜宵」）。所以 —— **能力在，尺子分裂**。两个数字各自成立，但没有一个可单独引用。

**更关键的分叉**：断点采样走**裸生成**（不经 `monitor`），产品通路走 `expression` 输出层。也就是说，**评估的是前者，用户用的是后者** —— 断点低分 ≠ 她说话时低分。报告自己也承认「断点采样…是模型真实倾向的观测口」。

**同一个病，在日常 ToMi 上表现得更极端**（本次拉 778 条 `prediction-errors` 实算）：

| real（现实标签） | 条数 | believed 命中 | believed 分布 |
|---|---|---|---|
| 低落 | 69 | **69/69 = 100%** | 低落 69 |
| 兴奋 | 46 | **46/46 = 100%** | 兴奋 46 |
| 轻微兴奋 | 12 | **12/12 = 100%** | 轻微兴奋 12 |
| **平静** | **651** | **0/651 = 0%** | 焦虑 455 / 轻微兴奋 186 / 兴奋 9 / 低落 1 |

整体 16.3% 的正确率**完全由这一行决定**：现实非平静时她 **127/127 全中**，现实平静时她 **0/651 全错**（一律判成焦虑或轻微兴奋）。

这不是 ToM 崩了，是**系统性偏置** —— 两种读法：

- **读法 A（尺子错）**：书库 sentiment 词典太弱，把有情绪的场景标成「平静」→ 她读对了，是尺子低估情绪强度。**Phase 0 就是修这个的。**
- **读法 B（她过度归因）**：她对中性消息一律套情绪 → 需要 ToM 侧加「无情绪」的负样本校准。

### ★ 定性：这是系统 bug，不是判断器问题（已定位到代码行，2026-09-03 13:30 已修复）

用 Phase 0 新情绪模块重新打分那 92 条 `feedback-live`（含 situation 原文）后，**读法 A 被排除**：

| 检验 | 结果 |
|---|---|
| `real=平静` 的 92 条里，新情绪模块判定**确实平静** | **87%**（80/92）—— 现实标签没错，是她判错了 |
| 她的 believed 分布 | 焦虑 61 / 轻微兴奋 30 / 兴奋 1 —— **无一条平静** |
| 文本推断链单独测（7 个真实句） | 6/7 判「平静」，只有「哈哈哈哈」判兴奋 → **她会判断，而且判断是准的** |

**真凶：`theory_of_mind.infer_owner_state` 第三条推断链无条件覆盖。**

```python
if mood_db and emotion == "平静":
    ent = entity_of(event_text)
    hist = query_mood_history(ent, db=mood_db)
    if hist:
        emotion = hist[0]["mood_label"]   # ← 无强度门槛、无时间衰减、无条件覆盖
```

而 `entity_of` 的实体泛化实测：

| 实体 | 情绪边数 | 桶内混杂标签 |
|---|---|---|
| **日常** | **5817 / 6512 = 89%** | 平静 + 兴奋 + 低落 |
| 邮件 | 422 | 平静 + 低落 + 兴奋 |
| 考试 | 87 | 平静 + 兴奋 + 低落 |
| …（去重实体仅 10 个） | | |

**89% 的事件被归进「日常」同一个桶**，桶里混着三种情绪。于是文本推断刚得出「平静」，立刻被这个大杂烩桶的最近一条边**无条件覆盖**成兴奋/低落/焦虑。

**所以 61/92 的「焦虑」根本不是她的判断** —— 是「日常」桶里最后写进去的那条边是什么，她就跟着说什么。

**附带第二个 bug：`mood_label_of(s, abs(s) + 0.3)` 强度注水。**

```python
def mood_label_of(sentiment, intensity):
    if sentiment > 0.3: return "兴奋" if intensity > 0.7 else "轻微兴奋"
    if sentiment < -0.3: return "低落" if intensity > 0.5 else "焦虑"
```
调用时 `intensity = abs(s) + 0.3`，即一旦跨过 |s|≥0.3 门槛，强度**从 0.6 起步**：
`s = -0.3 → intensity 0.6 > 0.5 → 判「低落」`（而非更保守的「焦虑」）。系统性偏向强标签。

> **同一个病根**：`entity_of` 泛化到「日常」，既是这里 believed 失真的原因，也是 §3.5 里「主人日常的事」×70 模板污染的原因。**修一处带两个。**

#### ⛔ 13:30 那版修法作废（用户指出：切断耦合 = 拿架构换数字）

我最初加的 `ent != "日常"` 守卫**违反架构设计**。`docs/Grace-V2.1-全模块协同逻辑.md` §5 明定：

```
ToM 读心依据（优先级）：
  显式传入 > 情绪图谱史（主人底色）> 事件情感推断 > ★暗注意力潜台词
```

即**图谱史本就该压过文本情感**（top-down 先验 > bottom-up 信号，预测编码正统）。我的守卫把这条优先级倒置——为了让指标好看而掐断项目最核心的一条耦合。**已回滚，耦合恢复。**

> 教训：耦合是特性不是 bug。信号脏应该去修信号源，不是拔掉连线。

#### 定稿：保留 3 项 + 链④ 转为诊断（2026-09-03 15:30）
