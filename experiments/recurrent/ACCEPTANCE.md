## 1. 框架浓度——三层正式定义（本验收单核心）

用户关切：LM 具有不可确定性，硬性框架进 LM 后会"变宽/泛化"，结果可能好但不可控。

设计的回答：**真正硬性的部分根本不进模型**（§11 三明治），泛化只被允许发生在有门限的两层：

| 层 | 测什么 | 谁保证 | R0 门限 | 失败处置 |
|---|---|---|---|---|
| **结构浓度** | 排布/K/守卫/阈值精确执行 | T0 代码断言（零梯度路径，物理隔离于权重外） | 100% | 断言失败即中止 |
| **能力浓度** | 循环插入后的能力保持 | 门限验收 | PPL(K2)/PPL(K1) ≤ 1.05 | R1 蒸馏立项 |
| **行为浓度** | 身份/方向行为不漂移 | 门限验收 | 探针一致 ≥ 4/5 | 缩段/降 K/R1 |

**推论**：循环骨架本身属于结构层（排布=代码），它**不可能被泛化软化**；会被软化的是能力/行为两层——而它们被门限看着，且退化可测、可回滚（重排是内存操作，重新 load 即完全还原）。

## 3. 关键技术事实（已核实源码/配置，非猜测）

- fused-rem-v61 = **Qwen3.8-27B（架构族 qwen3_5，混合注意力）**：64 层 = 48 线性注意力 + 16 全注意力，原生周期 `[3×linear + 1×full]`（`full_attention_interval=4`，config `layer_types` 实读）
- **默认循环段 = 中段一个原生周期 [32,36)（linear/linear/linear/full）×K=2**——按架构自己的重复单元循环，保持线性:全注意力比例不变；层位 64→68，权重仍 64 层
- mlx_lm `make_cache()` 遍历 `self.layers` 按层位建缓存（线性层 ArraysCache / 全注意力 KVCache）——**层表重排后缓存自动正确**（已核实 `mlx_lm/models/cache.py` 与 `qwen3_5.py:304`）
- 层表是普通 Python list（`Qwen3Model.__init__` 列表推导）——重排=纯内存引用操作，**重新 load 即完全还原**
- **意外红利**：线性注意力层本身就是序列上的循环结构（状态沿 token 传递）——Qwen3.5 已有一只脚在循环里，深度循环与它天然亲和
- **顺带实测点**：循环段上的 V6.1 人格 adapter 每轮生效一次——R0 顺带量化第一个"入环矩阵"的人格浓度变化

## 4. R0 执行时会发生什么（预告，验收后才跑）

1. 停 8100（防双驻留） → 2. 加载 27B → 3. **K=1 基线**（PPL 40 样本 + 5 探针生成）
→ 4. **层表重排 K=2** → 5. 同款复测 → 6. 报告（`report-r0.json/md`） → 7. trap 恢复 8100

预计 ~15 分钟；内存峰值 ≈ 常规 27B 推理（无新增权重）；延迟代价 ≈ +4/64 ≈ 6%。

## 6. 已知风险（首次真实运行时确认）

- K=2 裸循环**预期有退化**（文献：naive 循环 3-6 轮退化，9 轮崩溃）——R0 的目的就是量化它，作为 R1 蒸馏的立项证据；若退化超 5% 门限，属预期内失败，结论指向 R1 而非方案作废
- 探针一致性启发式为关键词级（雷姆/拉姆/姐姐/女仆）——R0 够用；R1 起可引入语义相似度
- 生成采样为默认参数（非贪心）会引入少量噪声——影响测量方差，不影响结论方向
